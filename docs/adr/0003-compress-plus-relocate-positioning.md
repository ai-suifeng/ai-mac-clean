# 产品定位：压缩与搬迁双承诺，v1 限定文件型工具

实测本机约 31G AI 工具数据，按 PRD 原口径（只压 jsonl）能腾出约 0.9G，且高度块状（其中一个 Codex 会话独占 2.38G，压缩率仅 28%）；而 Codex 已自动 zstd 压缩的 4.6G 数据重压缩收益为零。因此把定位从「压缩释放空间」改为**压缩 + 搬迁双承诺**：压缩仍是默认路径，同时把「迁往外置盘 / NAS」作为一等公民——搬迁腾出的是本机空间，不产生压缩收益，但不触碰任何红线（不碰缓存、不碰凭证、不解析 SQLite）。

v1 范围限定为实测确认的文件型工具：**Claude Code、Codex CLI、Cursor、DeepSeek Harness**。Gemini CLI / OpenCode（SQLite / `.pb` 私有协议）在实测出规则前仅展示占用。明确放弃扩大到缓存与扩展目录（Cursor AppSupport 14G、`~/.codex/.tmp` 879M 纯垃圾）——那是更大的空间，但违反「只归档、不乱动」的安全理念。

**Consequences**：

- 对 Claude Code 用户诚实：`~/.claude` 277M 中能归档的仅 404K（0.15%），97.5% 是受保护的 `plugins/` 与 `skills/`。宣传物料不得以 Claude Code 为主要收益案例。
- 预览页「压缩节省」与「搬迁腾出」分栏展示，话术为「大约小一半，经常 75–80%，有些会话几乎压不动」，禁止统一承诺 80%。
