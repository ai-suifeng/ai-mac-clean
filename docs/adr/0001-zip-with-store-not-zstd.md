# 归档格式选 zip + store，不用 zstd

归档包必须在卸载本软件后仍能被 macOS 自带工具打开（Archive Utility / `ditto`），这条硬要求否决了 zstd：实测 `zstd -19` 中位残量 0.3206，明显优于 deflate 的 0.4756，但它无法被系统工具解压，换来额外收益约 0.15G（在范围内 2.84G 未压缩数据上）。

**Consequences**：

- 已被工具自身压缩过的文件（Codex 的 `.jsonl.zst`）用 store 模式原样打包，不做无谓重压缩——实测重压缩收益趋近于零。
- 界面预览必须把「压缩节省」与「搬迁腾出」分成两栏，否则搬迁为主的用户会看到「预计释放 0」而困惑。
- ZIP64 已实测可用（5.6 GB 条目、2.96 GB 包，`unzip` 与 `ditto` 均逐字节一致）。
- 明确放弃的替代项：zstd -19（打不开）、tar+xz（无法单会话还原）、zip -9（最差文件收益恰为零，纯烧 CPU）。
